すでに「① 完了した予定の折りたたみ」および「② 翌日・候補へのクイック退避」は実装済みです。
以下の仕様 ③ 〜 ⑧ について、必要に応じて順次実装を進めてください。

> **取り込み状況（2026-10-19, Claude Code）**
> - ①② を取り込み。完了した予定を隠しているときに、区間（距離・高速の概算）とナビの「前の予定」が表示上の隣で決まっていた点、↑↓ が隠れた予定と入れ替わる点を修正（本当の前後で判定、`shiftVisible` を追加）。
> - ③〜⑧ を実装済み。⑤ のカテゴリ表記はアプリ既存の `CATEGORY_ICON` / `CATEGORY_LABEL` に合わせ、全カテゴリを選べるようにした。⑥ は地図のピン（候補を含む）と「次の予定」カードから日程タブへ移動する。⑧ の `budgetLimit` はマージ対象に追加し、データ用ガイドにも記載。

## 改善 ③: 時刻順の一括並べ替えボタン（プランニング効率化）

### 1. 概要・目的
予定を後から追加したり時刻を変更した際、↑↓ ボタンを連打することなく、ワンタップでその日の予定を時刻順に自動整列できるようにする。

### 2. 対象ファイル
- `src/components/DayTimeline.tsx`
- (既存ロジック利用: `src/lib/tripOps.ts` の `sortByTime`)

### 3. 仕様・UI 設計
- 各日のヘッダー（`day-side` 内、または「地図で見る」の横）に、**「⏰ 時刻順」** ボタンを配置。
- **表示条件**:
  - その日に時刻付き予定が 2 件以上あり、現在の並び順が `sortByTime(day.items)` と一致していない場合（または常時）。
- **動作**:
  - ボタン押下で `onChange(updateDay(trip, day.date, { items: sortByTime(day.items) }))` を実行。
  - 時刻なしの予定は相対的な前後関係を維持（既存 `sortByTime` の仕様通り）。

## 改善 ④: 滞在時間プリセットによる終了時刻の自動計算

### 1. 概要・目的
開始時刻 `time` と終了時刻 `endTime` を両方手動で時計ピッカーから入力するのは手間。「開始 10:00」の後に「+1時間」を押すだけで終了時刻が補完されるようにする。

### 2. 対象ファイル
- `src/components/SpotEditor.tsx`

### 3. 仕様・UI 設計
- 時刻入力欄（開始・終了）の直下に、以下のクイックチップを配置：
  - `+30分` / `+1時間` / `+1.5時間` / `+2時間` / `クリア`
- **動作**:
  - 開始時刻 `spot.time`（`HH:MM`）が入っている状態でチップをタップすると、分を加算して `spot.endTime` に `HH:MM` 形式でセット。
  - 例: `10:00` + `+1時間` → `11:00`
  - 日付をまたぐ場合（例: `23:30` + `+1時間`）は `00:30` としてセット。

## 改善 ⑤: 行きたい所リスト（Places）の「カテゴリ・★評価フィルター」

### 1. 概要・目的
行きたい場所が数十件以上に増えた際、「未訪問のカフェ・グルメだけ探したい」「★3（また行きたい）の場所だけ探したい」という絞り込みを可能にする。

### 2. 対象ファイル
- `src/routes/Places.tsx`

### 3. 仕様・UI 設計
- 検索バー・エリア選択の行（`.filters`）にフィルターを追加：
  1. **カテゴリ絞り込み**:
     - `全カテゴリ` / `観光 🏛️` / `食事 🍴` / `宿泊 🏨` / `その他 📌`
  2. **評価絞り込み**（「行った」「すべて」タブ選択時）:
     - `全評価` / `★★★ のみ` / `★★ 以上`
- **フィルタリングロジック**:
  - `shown` の絞り込み条件に `(!cat || p.category === cat)` および `(!ratingFilter || matchesRating(p.rating, ratingFilter))` を適用。

## 改善 ⑥: 地図とタイムラインの相互ジャンプ

### 1. 概要・目的
地図上のピンや下部の「次の予定」カードを見ていて、そのスポットのメモや予約番号、料金詳細を確認したい時、ワンタップでタイムラインの該当スポットへジャンプできるようにする。

### 2. 対象ファイル
- `src/components/MapView.tsx`
- `src/routes/TripDetail.tsx`
- `src/components/DayTimeline.tsx`

### 3. 仕様・UI 設計
- `MapView.tsx` のピン詳細（`SpotPopup`）および下部カード（`next-card`）に、**「🗓️ 日程で見る」** ボタンを追加。
- **動作**:
  1. 親の `TripDetail` へ通知し、タブを `plan`（日程）に切り替える。
  2. 該当スポット要素を `scrollIntoView({ behavior: 'smooth' })` で画面中央へスクロール。
  3. そのスポットを展開（`open = spot.id`）状態にしてアクションやメモを表示。

## 改善 ⑦: 位置未設定（緯度経度なし）スポットの可視化

### 1. 概要・目的
緯度経度がないスポットは地図画面にピンが出ず、見落としが発生しやすい。タイムライン上で一目で気づけるようにする。

### 2. 対象ファイル
- `src/components/DayTimeline.tsx`

### 3. 仕様・UI 設計
- タイムラインの各スポット行において、`s.lat == null || s.lng == null` の場合に小さく **`📍 位置未設定`** バッジを表示。
- バッジをタップすると、直接そのスポットの編集シート（地図指定・地名検索）を開く。

---

## 改善 ⑧: 目標予算（総予算枠）の設定と「残額メーター」

### 1. 概要・目的
旅行全体の予算枠（例: 100,000円）を設定し、現在の予定の合計に対して「あといくら使えるか」「予算オーバーしていないか」を直感的に把握できるようにする。

### 2. 対象ファイル
- `src/types/trip.ts` (Zod スキーマ拡張: `budgetLimit?: z.number().positive().optional()`)
- `src/components/BudgetView.tsx`

### 3. 仕様・UI 設計
- **スキーマ更新**:
  - `TripSchema` に `budgetLimit` を追加し、`npm run schema` で JSON Schema を再生成。
- **UI 表示**:
  - `BudgetView.tsx` の合計カード内に「目標予算: [ 100,000 ] 円」の入力欄を配置。
  - 目標予算が設定されている場合：
    - **残額表示**: `残り ¥35,000`（または `⚠️ ¥5,000 オーバー`）
    - **プログレスバー**:
      - 使用率 80%未満: 緑 (`--ok`)
      - 80〜100%: オレンジ (`--warn`)
      - 100%超: 赤 (`--err`)
