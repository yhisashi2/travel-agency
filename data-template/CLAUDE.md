# Travel Agency データリポジトリ

このリポジトリは旅行計画アプリ「Travel Agency」のデータ置き場です。アプリ（スマホ/PC）と Claude Code の両方から同じファイルを編集します。

## ファイル
- `trips/<id>.json` … 旅行 1 件 = 1 ファイル。ファイル名（拡張子なし）と `id` を一致させる
- `places.json` … 旅行に関係なく「いつか行きたい所 / 行った所」をためる全体リスト
- `schema/trip.schema.json`, `schema/places.schema.json` … JSON Schema（編集後は必ずこれに適合させる）

## 旅行（trips/*.json）の要点
- `days[]` は `startDate`〜`endDate` の各日 1 要素（`date` は `YYYY-MM-DD`）。期間を変えたら `days` も合わせる
- **日程未定の旅行**: `startDate` / `endDate` を省略し、`days` は空配列。候補はすべて `ideas[]` に入れる。`destination`（目的地。例 `九州`）と `durationDays`（目安の日数）を付けられる
- 日程が決まったら `startDate` / `endDate` を入れ、その期間の `days` を作って `ideas` から Spot を移す（Spot の `id` はそのまま）
- `days[].items[]` と `ideas[]`（その旅行で日程未定の候補）は同じ Spot 形式
- Spot の必須は `id`（一意な英数字。新規は 8〜12 文字のランダム英数字）と `title`
- `category`: `sightseeing` | `food` | `lodging` | `transport` | `other`
- `time` / `endTime`: `HH:MM`（24 時間、ゼロ埋め）。items は時刻順に並べる
- `lat` / `lng`: 地図とルートに必要。分かる場合は必ず入れる（小数 4〜6 桁）
- `transportToNext`: 次の予定への移動手段 `walk` | `car` | `bike`（バイク） | `train` | `bus` | `ferry`（フェリー） | `flight`。フェリーに乗る港の Spot には `ferry` を入れる
- `cost` は数値、`currency` は ISO 4217（省略時は `baseCurrency`）。外貨は `rates` に「1 単位 = 何 baseCurrency」を入れる
- `done`: 旅行中にアプリで付ける完了フラグ。理由なく変更しない
- `placeId`: `places.json` の場所と同じものなら、その `id` を入れる
- `updatedAt` は編集したら現在時刻（ISO 8601）に更新

## 行きたい所リスト（places.json）の要点
- `places[]` の各要素: `id`, `title`, `category`, `area`（都道府県や国。例 `熊本県`, `France`）, `lat`/`lng`, `address`, `url`, `memo`
- `visits[]`: 行った記録 `{ "date": "YYYY-MM-DD", "tripId": "..." }`（日付・旅行は不明なら省略可）。**空配列 = まだ行っていない**
- `rating`: 行った場所のお気に入り度 `1`（まあまあ）| `2`（良い）| `3`（また行きたい）。未訪問なら付けない
- アプリでは、旅行中に予定を「完了」にすると自動で `visits` に記録され、評価を聞かれる
- 既存の場所の `id` は変えない。同じ場所を重複登録しない（名前と位置で確認する）
- `home`（任意）: 自宅 `{ "title", "lat", "lng", "address" }`。アプリの設定画面で登録する。旅行の出発・帰着地として扱う

## プランを作る・候補を出すときのルール（重要）
1. まず `places.json` から、旅程のエリア・ルートの近くにある **未訪問（`visits` が空）** の場所を優先して組み込む
2. 次点は行ったことがあっても `rating: 3`（また行きたい）の場所
3. `rating` が 1〜2 の訪問済みの場所は、ユーザーが希望したとき以外は入れない（入れる場合は `memo` に「再訪」と書く）
4. リストに無い場所を新しく提案するときも、`places.json` で行ったことがある場所は避ける
5. `places.json` の場所を予定に入れたら、Spot に `placeId` を付ける
6. 提案の最後に「未訪問 N 件 / 再訪 M 件」を一言添える
7. `places.json` に `home` があれば、初日は自宅から出発・最終日は自宅へ帰着する前提で移動時間・距離を考える（バイク旅なら 1 日の走行距離にも注意）
8. 「目的地だけ決まっていて日程は未定」の依頼では、日程未定の旅行（上記）として作り、目的地の候補を `ideas` に入れる。回る順番の目安や必要日数は `notes` に書く

## 編集ルール
- 既存 Spot / Place の `id` は絶対に変えない（アプリ側の同期マージが id 単位のため）
- 予定を別の日へ移すときは Spot オブジェクトごと移動する（コピーして新 id にしない）
- JSON は 2 スペースインデント、末尾改行あり
- 1 回の依頼ごとに分かりやすいコミットメッセージでコミットし、プッシュする
- アプリが読むのは `main` ブランチ。別ブランチや PR で作業した場合は、`main` にマージされるまでアプリには表示されない
- 天気・営業時間など不確かな情報は `memo` に「要確認」と書く

## よくある依頼の例
- 「2 日目の午後に浅草寺を追加して」→ 該当日の items に時刻・座標付きで追加し、時刻順に並べ替え
- 「雨なので 3 日目の屋外予定を屋内に差し替えて」→ 屋外 Spot を `ideas` に移し、屋内候補を追加
- 「予算を集計して」→ items の cost を rates で換算して合計を回答（ファイルは変更しない）
- 「行きたい所に〇〇を追加して」→ `places.json` に座標・エリア付きで追加（`visits` は空）
- 「〇〇は去年行った、すごく良かった」→ その場所の `visits` に記録を足し `rating: 3`
- 「東北 3 泊 4 日のプランを作って」→ 上のルールに従い、未訪問の場所を中心に `trips/` に新しい旅行を作成
- 「日程は未定だけど四国に行きたい。候補を出して」→ `startDate` なしの旅行を作り、`destination: "四国"`、未訪問の場所を中心に `ideas` に追加
- 「さっきの四国、11/3〜11/6 に決まった」→ `startDate` / `endDate` と `days` を作り、`ideas` の Spot を自宅からの移動も考えて各日に振り分ける
